# ADR-071 — Checkpoint 10.3: academic intelligence is a deterministic, explainable extension of the academic read model; the mobile client gets a token-based design system

**Status:** Locked

**Checkpoint 10.3 — Academic Intelligence Expansion + Mobile UX Modernization (2026-09-16, owner-directed).** Two objectives, one checkpoint, no migration. **1. ACADEMIC INTELLIGENCE IS COMPUTED, DETERMINISTIC AND EXPLAINABLE — NEVER A MODEL CALL.** The questions the brief asks ("what needs attention today, what is approaching, which courses need focus, am I falling behind, what should I do next") are answered by four new sections computed inside the existing `GET /academic/today` build — the same one `effectiveNow`, the same current-term scope (ADR-070a), the same local-day windows as the Overdue / Due today / Due this week buckets — and one on `GET /academic/courses/:id`, all in pure `packages/core/src/academic/` functions (`urgency.ts`, `workload.ts`, `grade-summary.ts`): **urgency** is a ladder over the bucket boundaries (`critical` ⟺ overdue; `high` ⟺ due within 24 h; `medium` ⟺ due before the end of the seven-day horizon; `low` otherwise; undated is never urgent); **priority** is an integer score over a closed reason vocabulary in the ADR-065 search-scoring idiom (base points by urgency 400/300/200/100, plus `marked_missing` +50, `marked_late` +25, `high_points` +25 at ≥ 50 points), ranked score → due → title → id, capped at five with an honest total — every item carries `urgency`, `score` and `reasons`, so the ranking is recomputable by hand from the row; **workload** reports the counts a status is derived from and the status itself (`behind` ⟺ any overdue or missing; else `at_risk` ⟺ anything due within 24 h; else `on_track`) plus a per-local-day due/points strip for today and the seven following days and the points at stake inside the horizon; **course attention** is a threshold per current-term course (`high` ⟺ overdue or due within 24 h; `medium` ⟺ due this week; `low` ⟺ anything open) ordered by level, then overdue, then next due; and a **grade summary** per course (graded count, mean percentage, points-weighted percentage over graded rows carrying both a score and a maximum — an excused graded row counts in the total only). None of these rules blends weights or reads a clock, so the reader can always see WHY. **2. THE WIRE GROWS ONLY THROUGH OPTIONAL TOP-LEVEL KEYS.** The deployed versionCode-25 client parses every academic item schema as `.strict()` (the regression the 10.2 review caught), so `priorities`, `workload`, `course_attention` and `grade_summary` are OPTIONAL keys on the non-strict response objects — the `current_term` precedent — and no existing `.strict()` item schema gained a field; a server never omits them, a not-configured server sends them zeroed, and a schema test pins that the pre-10.3 response shape still parses and that `urgency` is rejected on an assignment item. **3. THE AI BOUNDARY IS UNCHANGED AND RE-GUARDED.** Everything above lives in `read-models/academic.ts` and `packages/core/src/academic/`, both denied to `intelligence/`, `ask/`, `focus/` and `brief/` by egress Guard 5, which passed unmodified; the only client-side derivation remains the course detail's partition-and-urgency of already-open rows against the query's own `dataUpdatedAt`, the permitted derivation the 10.2 detail screen already documented. **4. THE MOBILE CLIENT GETS A DESIGN SYSTEM, NOT A RESTYLE.** One token file (`apps/mobile/src/components/ui/tokens.js` — Material 3 colour roles with a dark sibling per role, a seven-step type scale, card/inner radii, three shadows, six gradient presets) feeds Tailwind at build time and `theme.ts` at runtime, pinned equal by test, and a primitive set (`Screen`/`ScreenHeader`, `Card`/`GradientCard`, `SectionHeader`, `ListRow`, `StatusChip`, `MetricCard`, `ProgressBar`, `Button`/`IconButton`, `EmptyState`/`ErrorState`, skeletons, `Icon`, `triggerHaptic`, plus three composites — `ChoiceChip`, `TextField`, `SegmentedControl` — that live beside their first consumer until a fourth domain needs them) is what screens compose; a screen writes no hex or Tailwind-palette colour class of its own, and a token pair appears only inside a component with no primitive to lean on (`docs/MOBILE-DESIGN-SYSTEM.md` lists the exceptions). Three Expo SDK 57 modules join the client for this — `expo-linear-gradient` (the one gradient per screen), `expo-haptics` (feedback on meaningful taps only, no-op on web) and `@expo/vector-icons` (Material Community Icons; `expo-symbols`, already present, renders nothing on the Android daily driver) — a native rebuild, which every client change already requires. **One pre-existing web defect fixed in passing:** `tailwind.config.js` has pinned `darkMode: "class"` since Phase 2, but nothing ever set the `dark` class on the document, so on the dev server a browser in dark mode drew a dark navigator over light content, and on the static export the interop runtime pinned the scheme to "light" at boot (no class on `<html>` when the stylesheet is already applied) so dark mode never engaged at all; `useSyncWebColorSchemeClass` now calls NativeWind's `colorScheme.set("system")` once at boot and keeps the `dark` class in step with the hook — verified on a static `expo export` under `prefers-color-scheme: dark`, which the independent review correctly predicted the class-sync alone would not survive (native needs nothing). **Contrast is a tested contract, not a preference:** the review measured the palette's first cut at 2.3:1 for white-90 on the light health gradient and 3.2:1 for muted captions; the tokens were darkened and `theme.test.ts` now pins every text role ≥ 4.5:1 on every surface and white / white-90 ≥ 4.5:1 on every gradient stop. **Unchanged:** ADR-018 (no new ingress), ADR-024, ADR-056 (no embeddings, no write-capable lane), ADR-058 (no new alert producer), ADR-065 (Canvas rows stay outside search), ADR-066/067, ADR-068/068a storage, ADR-070/070a (read model, current term). **Not done here:** production deployment and the Rabbit APK — the brief's own gate is implementation → tests → independent review → migration safety → rollback plan → deployment, and this record closes at the review (Checkpoint 10.3, 2026-09-16)
