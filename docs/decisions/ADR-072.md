# ADR-072 — Checkpoint 10.4 (Lane 1): "Focus Now" is a deterministic, client-side merge of two already-fetched read models; no new route, no new database access, no AI call

**Status:** Locked

**Checkpoint 10.4, Lane 1 — "Focus Now" (2026-09-16, owner-directed).** The Today screen already
renders two independently-owned, ranked lists that both answer some part of "what needs me right
now": Today's own `overdue`/`due_today` task buckets, and the Academics card's server-ranked "Do
next" candidates (`AcademicTodayResponse.priorities`, Checkpoint 10.3, ADR-071). Neither list knows
the other exists, so a genuinely urgent academic assignment can sit below a merely on-time personal
task, or vice versa, with no way to tell which one is actually most urgent right now. Focus Now
closes that gap with ONE merged, ranked, capped, explainable list — deterministic throughout, no
model call anywhere in it.

**1. THE MERGE IS CLIENT-SIDE BY STRUCTURAL NECESSITY, NOT PREFERENCE.**
`apps/api/src/ask/ai-egress-guard.test.ts`'s Guard 5 forbids every file under
`apps/api/src/read-models/` — `today.ts` included — from importing the academic read model or
naming a Canvas table at all, the same privacy wall ADR-046 established for Health and ADR-070
extended to Canvas. A server-side `/today` that also returned academic priorities is therefore off
the table by construction; a new merged route would need its own privacy argument this checkpoint
does not attempt to make, and duplicating Guard 5's exemption for a new file was rejected as the
same risk with extra surface. The merge instead happens entirely in the already-permitted client
lane: ADR-071 documented that the course detail screen derives urgency client-side against a
query's own `dataUpdatedAt` as "the one permitted client derivation"; Focus Now is a second,
narrowly-scoped instance of that same precedent — never a new exception.

**2. THE SCORER LIVES IN `packages/core/src/focus-now/score.ts`, A NEW CLIENT-SAFE SUBPATH.**
Mirroring `./academic/*`'s own `package.json` export shape (`"./focus-now/*":
"./dist/focus-now/*.js"`), this module is pure and total: no clock read (the caller passes
`effectiveNow`, and for a task, the same `horizonEndUtc` `academicTodayWindows` already computes),
no database, no Node builtin. It does not import `@personal-os/schema` (core never does, to avoid a
cycle — schema imports core, not the reverse), so its `FocusNowCandidate` shape
(`{id, kind, title, dueAt, score, reasons}`) is a generic, duck-typed interface the mobile layer
adapts wire types onto.

**3. A PERSONAL TASK IS SCORED FRESH, ON THE SAME LADDER AN ASSIGNMENT USES — REUSED, NOT
REIMPLEMENTED.** `scoreFocusNowTask` calls `deriveUrgency` and reads `ACADEMIC_URGENCY_BASE_POINTS`
directly from `packages/core/src/academic/urgency.ts` rather than restating the ladder's boundaries,
so a critical task and a critical assignment sit on the identical 400/300/200/100 scale and explain
themselves with the identical reason words ("Overdue", "Due <24h", "This week"). The one task-only
addition is `top_priority` (+25, the same additive scale as `marked_late`/`high_points`): Personal
OS's own priority convention is lower value = higher priority (`docs/ARCHITECTURE.md` "Today &
agenda read models" rule 6), so `priority === 1` (P1) is the one value worth rewarding. In today's
actual wiring — Today's `overdue`/`due_today` buckets, which is all a task candidate is drawn from —
only `critical` and `high` are ever reachable (nothing in those buckets is ever more than 24h out by
construction), but the scorer stays total and general rather than special-cased to that fact.

**4. AN ACADEMIC CANDIDATE'S SCORE IS NEVER RE-DERIVED — ONLY WRAPPED.**
`focusNowCandidateFromAcademic` copies `score`/`reasons` verbatim from the server's own
`AcademicPriorityItem` (itself computed by `scoreAcademicPriority`, ADR-071). Recomputing it
client-side would risk the two numbers silently drifting apart across a future scoring-rule change;
copying makes drift structurally impossible.

**5. RANKING IS ACADEMIC'S OWN COMPARATOR, RE-EXPORTED RATHER THAN COPIED.**
`FocusNowCandidate` structurally satisfies `AcademicPriorityCandidate` (`id`/`title`/`dueAt`/
`score`), so `compareFocusNowCandidates` and `rankFocusNowCandidates` are the literal
`compareAcademicPriorities`/`rankAcademicPriorities` functions, generic enough to also rank the
mobile layer's richer per-kind row types (`FocusNowTaskRow`/`FocusNowAcademicRow`, which merely
extend the candidate shape with the originating task or priority item for the card to render). The
order — score desc, then `dueAt` asc with nulls last, then title asc, then id asc — is therefore
byte-identical in shape to every other ranked read model this project ships
(`docs/ARCHITECTURE.md`'s "every read-model ordering ends in id" rule), capped at `FOCUS_NOW_CAP`
(5).

**6. THE MOBILE CARD OWNS BOTH SOURCE QUERIES AND ADDS NEITHER A ROUTE NOR A NETWORK CALL.**
`components/today/focus-now-card.tsx` calls `useToday()` and `useAcademicToday()` directly — the
same two hooks the Today screen and the Academics card already call — so React Query dedupes by
query key rather than firing a third fetch. It renders nothing at all (not an empty state) while
either source is loading or erroring, mirroring `AcademicTodayCard`'s own posture, and an academic
row opens through the existing single gated call site (`components/academic/source-link.tsx`'s
same-origin check) rather than a new one — no new entry in
`apps/worker/src/mobile-inert-rendering.test.ts`'s `OPEN_URL_ALLOWED` allowlist was needed, because
the card never calls `Linking` itself.

**7. NOTHING NEW REACHES AN AI LANE, A DATABASE, OR A CONSENT SURFACE.**
Every input to Focus Now is data the Today screen and the Academics card already fetched and
already display elsewhere; nothing is stored, nothing is sent to a model, and no route, migration,
queue job, or consent switch was added. Guard 5, Guard 4 (the no-write/no-`ai`-import rule under
`apps/api/src/intelligence/`) and every academic/Canvas boundary from ADR-068/070/071 are unaffected
by construction — this feature lives entirely in `packages/core` and `apps/mobile`.

**Unchanged and reaffirmed:** ADR-018 (no new ingress), ADR-024, ADR-046/056 (no AI processing of
Health or academic data; read-only before write-capable), ADR-058 (no new alert producer), ADR-065
(Canvas rows stay outside search), ADR-066/067 (Ask/Suggested Focus untouched — Focus Now is not a
third intelligence lane, it is zero intelligence lanes), ADR-068/068a/070/070a/071 (the Canvas and
academic read models, unmodified).
