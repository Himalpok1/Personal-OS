# ADR-075 — Checkpoint 10.6 (Intelligence): explainable, context-aware Focus Now and a deterministic daily briefing, composed on the client over already-fetched read models; one opaque optional key on `/today`

**Status:** Locked

**Checkpoint 10.6, intelligence pillar (2026-09-17, owner-directed).** The owner's brief for this
phase asks Personal OS to move from "here is your information" to "here is what matters, why it
matters, and what you can do next" — with every recommendation deterministic, traceable to a source,
free of black-box scoring, and without unnecessary AI calls, a premature agent architecture or
speculative schema. A bounded review preceded any code (two read-only lanes: intelligence and
mobile UX). Its central findings shaped this record: (1) everything a "why" needs is already on the
wire or one join away; (2) the only structural gap is that `GET /today`'s task items do not carry
the one typed relationship Checkpoint 10.5 added (`tasks.canvas_assignment_id`, ADR-074), so the
client cannot tell that a task IS an assignment's own reminder; (3) `AcademicPriorityReasonSchema`
is a closed `z.enum` inside a `.strict()` item that the deployed versionCode-29 client parses with
`schema.parse`, so a NEW server-side reason would blank both the Academics card and Focus Now on
every installed device until a rebuild — while `TodayTaskItemSchema` is a plain `z.object` whose
optional keys an older client simply strips.

**1. EXPLAINABILITY IS A CLOSED VOCABULARY WITH A SOURCE, NOT PROSE.** Every Focus Now reason —
academic's six (`overdue`, `due_within_24h`, `due_this_week`, `marked_missing`, `marked_late`,
`high_points`), the task-only `top_priority`, and six new CONTEXT reasons (`linked_assignment`,
`project_stalled`, `course_attention_high`, `no_submission`, `reminder_set`, `snoozed`) — maps
through ONE frozen table (`packages/core/src/focus-now/explain.ts`) to a label, a one-sentence
deterministic "why", and a `source` from a closed set (`task`, `reminder`, `project`,
`canvas_assignment`, `course`, `calendar`). A row's score is auditable from the row itself: the
client renders the equation (`400 overdue + 25 P1 + 25 linked assignment = 450`) so a ranking claim
can be checked against frozen point tables, the ADR-065/ADR-071 discipline applied to the merged
list. No model authors any of this text.

**2. CONTEXT MAKES A ROW MORE IMPORTANT ONLY THROUGH A FROZEN, SMALL, ADDITIVE TABLE.** The brief's
own rule — a task matters more when it has a deadline AND a connected course/project AND no
progress — becomes `FOCUS_NOW_CONTEXT_POINTS`: `linked_assignment` +25, `project_stalled` +25,
`course_attention_high` +25 (the same additive scale as ADR-071's `marked_late`/`high_points`), and
`no_submission`, `reminder_set`, `snoozed` at 0 — informational reasons that explain but never
reorder. Every candidate carries `baseScore` (a task's urgency score, or an assignment's server score
VERBATIM), `contextPoints`, and `score = baseScore + contextPoints`. ADR-072's rule that the client
never re-derives an academic score therefore still holds exactly: context is a separately listed
layer on top, never a recomputation underneath.

**3. A TASK LINKED TO AN ASSIGNMENT IS ONE ROW, AND THE TASK IS THE ROW.** `GET /today`'s task items
gain `canvas_assignment_id: uuid | null` — OPTIONAL, wire-safe for the deployed client, an opaque
identifier only. `/today` feeds both AI collectors (`brief/collect-input.ts`,
`intelligence/today-context.ts`), and both map fields explicitly, so the id reaches no model; a Canvas
title never crosses (a route test pins that the assignment's title is absent from the response).
With that id, `mergeLinkedCandidates` collapses a task and the priority item it links to into ONE
candidate of kind `task` — the thing the owner can complete in-app — with the max of the two base
scores, the union of both reason lists, the `linked_assignment` bonus, and the assignment id retained
for display. A task linked to an assignment that is not in the candidate list is unchanged.

**4. THE DAILY BRIEFING IS A DETERMINISTIC CLIENT COMPOSITION, NOT A NEW READ MODEL.** Guard 5 keeps
academic data out of `/today` structurally, and ADR-046 keeps health out of every AI-visible object;
a server-side "briefing" route could therefore contain only what `/today` already says. The
briefing is instead `composeBriefing` in `packages/core/src/focus-now/briefing.ts` — pure logic over
the responses the Today screen ALREADY fetches (`/today`, `/academic/today`, `/health-summary`) and
the merged Focus Now list, producing sections (`academic`, `schedule`, `health`, `focus`) whose every
line carries a source label and, where it names an item, a typed `ref`. A section with nothing to
say is omitted, never invented; the health line renders only when both the latest sleep session and
the seven-day average exist and the wake date is today or yesterday. Free study blocks
(`free-blocks.ts`) are pure arithmetic over today's timed events inside an 08:00–22:00 local window,
DST-safe through `packages/core`'s wall-clock helpers, with a 60-minute minimum. Nothing is stored,
scheduled or sent anywhere; the AI Daily Brief (ADR-041/043) is unchanged and remains a separate,
explicit, model-authored surface.

**5. WHAT WAS DELIBERATELY NOT DONE.** No new member of `AcademicPriorityReasonSchema` and no new key
on any `.strict()` academic item schema (finding 3 above); no mail signal on Today beyond the
existing digest (a deterministic unread count would need a new metadata read model over
`mail_messages.provider_labels` — its own ADR-053/054 argument); no server-side merged read model; no
new AI surface; no migration; `apps/worker` untouched.

**Consequences.** Focus Now explains itself completely from the row (`explanations`, `equation`),
combines task, project, course, reminder and calendar context deterministically, and shows one row
per real-world obligation. The Today screen carries a briefing that reads like the brief's own example
without a single model call. The one wire change is additive and optional; the versionCode-29 client
keeps parsing every response. Every future context reason is a new row in two frozen tables plus a
test, never a formula change.
