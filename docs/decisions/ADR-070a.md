# ADR-070a — Amendment to ADR-070: academic surfaces show the current term only, selected by date, never by name

**Status:** Locked

**Amendment to ADR-070 (2026-09-16, Checkpoint 10.2, owner-directed).** After the first day on the deployed Academic Intelligence Layer the owner's Today card read `OVERDUE · 11`, most of it Spring 2026 coursework and undated "Default Term" compliance trainings due in March — a faithful projection of everything Canvas returns, and useless as a command centre. The owner's decision: **Canvas information in the app comes from the current term (Fall 2026) only, not older courses.** Implemented as a deterministic, date-driven rule in `packages/core/src/academic/current-term.ts`, never a hard-coded term name: the current term is the **most recently started** term — the latest `term_start_at` at or before the build's one `effectiveNow` — identified by its start instant. A course with no `term_start_at` (Canvas's "Default Term") is never current; an ended term stays current until the next one starts (the winter gap shows Fall, not nothing); the rule rolls over on its own the day the next term begins; and when no course carries a started term there is no basis to filter and every course is treated as current. `GET /academic/today` applies it to every course-scoped section (a personal, course-less calendar event is never term-filtered); `GET /academic/courses` defaults to the current term with `include_past_terms=true` to browse older ones; `GET /academic/courses/:id` still opens any course by id. Both responses echo `current_term` so a client can label what it shows. **The sync is unchanged** — every term's rows are still cached, still searchable by nothing, and still available to the detail route; the filter lives in the read model, where "computed, never stored" (ADR-070 §1) keeps a product rule reversible without a migration. Unchanged: ADR-068/068a storage, ADR-070's structural AI boundary (Checkpoint 10.2, 2026-09-16)
