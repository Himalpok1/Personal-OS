# ADR-076 — Checkpoint 10.6 (Mobile): motion, gestures and interaction primitives added to the design system on the already-installed Reanimated/gesture-handler stack; Today reorganised actionable-first

**Status:** Locked

**Checkpoint 10.6, mobile pillar (2026-09-17, owner-directed).** The brief makes the mobile
experience a primary product feature, not a polish step: the app should feel like a polished
consumer product — smooth transitions, subtle animation, haptics, swipe actions, expandable cards,
quick actions — while keeping every ADR-071 rule (tokens only, light and dark, tested contrast,
44px targets, one gradient per screen, skeleton-where-it-will-appear, no clock reads in render).
The bounded mobile review found that nothing in `apps/mobile/src` animates beyond two `Animated`
opacity loops, that no gesture exists anywhere, that the two most-used surfaces (Today's task rows
and the Tasks list) offer no quick action beyond a hand-rolled completion circle copied three times,
that every academic row bounces the owner out to Chrome, and that on the Rabbit R1's 480×640 screen
the actionable Today sections sit below five cards. It also established the decisive engineering
fact: `react-native-reanimated@4.5.1`, `react-native-gesture-handler@2.32` and
`react-native-worklets` are ALREADY direct dependencies of `apps/mobile` (pulled in by Expo Router),
present in every shipped APK, and `babel-preset-expo` auto-wires the worklets plugin — so motion and
gestures cost no new dependency and no native change.

**1. MOTION IS A DESIGN-SYSTEM CONCERN WITH ONE VOCABULARY.** `components/ui/motion.ts` owns the
durations, springs and entering/layout presets every screen uses; a screen never writes its own
timing. Motion never blocks: a reduced-motion user (Reanimated's `useReducedMotion`) and the web
target get the same end state instantly, and every animated wrapper is a thin LEAF so the project's
hookless tree-walk test idiom keeps working around it (the pure decision helpers are what tests pin).
The web build is verified once on a static `expo export`, the same way 10.3 verified dark mode.

**2. QUICK ACTIONS ARE GESTURES WITH A VISIBLE FALLBACK.** `SwipeableRow` (over gesture-handler's
`ReanimatedSwipeable`, under a `GestureHandlerRootView` mounted once at the root) gives Today's task
rows, the Focus Now rows, the Tasks list and Notes swipe-to-complete / snooze / archive with
token-coloured action panels and a haptic on commit (Inbox gained an Open / Dismissed segmented
control instead — its rows' one action is a confirm button). On web the row renders its children only and every action stays
reachable through the row's own controls or the detail screen — a swipe is an accelerator, never
the only path. `CompletionCircle` replaces the hand-rolled checkboxes on Today and Agenda (and is what the new
Tasks-list and Focus Now rows use) with one spring-filled, haptic-on-complete control that keeps
`stopPropagation` and `containsControl` semantics; the project screen's own circle is a recorded
leftover.

**3. FEEDBACK IS IMMEDIATE AND UNDOABLE WHERE THE DATA ALLOWS.** `PressableScale` (a 0.97 spring on
press) underlies `Card`, `Button`, `IconButton` and `MetricCard`; `Toast` (a root-mounted host with
a module-level `showToast`, so hookless cards can call it from a mutation's `onSuccess`) confirms
completions, sync requests and archives with an optional action; `AnimatedNumber` counts hero and
metric values in; `BottomSheet` hosts the in-app assignment detail so an academic row opens a sheet
(title, course, due, points, submission, the Focus Now explanation) and only THEN offers "Open in
Canvas" through `SourceLink` — still the one gated `Linking.openURL` call site.

**4. TODAY IS ORGANISED ACTIONABLE-FIRST.** The screen order becomes: header → the daily briefing
(ADR-075, replacing the counts-only hero as the one gradient block) → reminder notice → Focus Now
with its explanations → Overdue → Due today → Events → Brief / Health / Mail / Academics → reviews →
Upcoming → Inbox → Projects. The duplicate stat row (the same counts 100px apart) is removed; Focus
Now rows carry a completion circle and swipe actions; upcoming rows are pressable; the events
section uses the shared `EmptyState`. The source-regex tests that pinned the old positions are
updated to the new order deliberately, never loosened.

**5. WHAT WAS DELIBERATELY NOT DONE.** No new npm dependency (no moti, lottie, svg, bottom-sheet
library); no change to the calendar grids' geometry or the FAB/PTT band (both verified on-device
in earlier checkpoints); the Settings hub split and a persisted appearance preference are recorded
as candidates, not built; no wire change belongs to this pillar.

**Consequences.** The app gains a single motion and gesture vocabulary with no new dependency and
no native rebuild beyond the ordinary JS APK; every new primitive follows ADR-071's token, contrast,
target-size and testing contracts and is documented in `docs/MOBILE-DESIGN-SYSTEM.md`; the busiest
screen leads with what to do and why. Reanimated worklets are exercised in production for the first
time, so the release gate adds a static web export check and an on-device walk of every animated
surface in both colour schemes.
